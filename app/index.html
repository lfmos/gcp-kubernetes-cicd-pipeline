01

O PROJETO

ENTREGA CONTÍNUA

Do código ao cluster,
com rastreabilidade.

O projeto demonstra um fluxo de entrega moderno: cada alteração passa por validação, geração de imagem Docker, publicação no Artifact Registry e atualização controlada do workload no GKE.

A aplicação também pode ser publicada gratuitamente no GitHub Pages, permitindo apresentar uma versão funcional no portfólio sem manter infraestrutura em nuvem ativa.

02

PIPELINE

AUTOMAÇÃO

Fluxo de entrega

TRIGGER: PUSH / MAIN

  1. 01
    </>

    Commit

    O código é versionado e enviado para o repositório central.

    git push origin main
  2. 02
    ✓

    Validate

    Arquivos essenciais, manifests e configuração são verificados.

    stage: validate
  3. 03
    ▣

    Build

    A aplicação é empacotada em uma imagem NGINX não privilegiada.

    docker build
  4. 04
    ⇧

    Publish

    A imagem recebe uma tag imutável e é enviada ao Artifact Registry.

    $CI_COMMIT_SHORT_SHA
  5. 05
    K8s

    Deploy

    Os manifests declarativos são aplicados ao namespace de produção.

    kubectl apply
  6. 06
    ◎

    Verify

    O rollout é acompanhado até a confirmação de disponibilidade.

    rollout status
